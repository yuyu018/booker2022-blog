布克小姐網站｜審核者手冊

給網站主人。寫稿人送出的每一次修改都要經過你同意才會上線，這份手冊說明怎麼看、怎麼放行、出事怎麼查。

一、整個流程長這樣

寫稿人另開草稿→ 編輯並儲存→ 送出審稿→ 你檢查→ 合併＝上線

他不管怎麼操作都碰不到正式網站——GitHub 的分支保護會擋下來。只有你（管理員）能放行。

二、待審稿在哪裡看

待審清單github.com/yuyu018/booker2022-blog/pulls
改了什麼點進該筆 → Files changed 分頁。綠色是新增、紅色是刪掉
實際畫面該頁下方 Vercel 會留一個預覽網址，點開就是套用後的樣子
還沒送審的草稿github.com/yuyu018/booker2022-blog/branches，名稱都是 draft- 開頭

GitHub 預設會把待審通知寄到你的信箱，不必一直開著網頁等。

三、放行或退件

  1. 打開該筆審稿，看 Files changed 確認內容。
  2. 要上線 → Merge pull request → Confirm merge。網站幾分鐘後自動更新。
  3. 不要 → Close pull request（退件，內容還留著，之後可再開）。
  4. 合併或退件之後，按 Delete branch 把用完的草稿清掉，清單才不會愈積愈多。
合併前必看的兩件事
  1. 內容有沒有出現真實姓名、公務單位、他人個資——這個站是公開的。
  2. 是不是動到 2026 年 9 月前從 Facebook 搬過來的舊文章。那些文章的斷行用後台編輯會跑掉，看到就先退件。

四、你自己要改文字

你是管理員，有兩條路，都不用經過審稿：

線上改missbooker.com/keystatic，左上角保持在 正式版，儲存後直接上線。適合改錯字。
在自己電腦改終端機執行 npm run dev，打開 localhost:4321/keystatic。這是本機模式，不用登入 GitHub，改完自己 git push。適合大幅修改。

五、管理協作者

  1. 邀請或移除：repo → Settings → Collaborators。
  2. 權限一律給 Write。
  3. 不要給 Admin——管理員會繞過審稿保護，可以直接改正式網站。

六、設定備忘（出問題時對照）

後台網址missbooker.com/keystatic
GitHub Appmissbooker editor（回呼網址 /api/keystatic/github/oauth/callback）
Vercel 環境變數KEYSTATIC_GITHUB_CLIENT_ID、KEYSTATIC_GITHUB_CLIENT_SECRET、PUBLIC_KEYSTATIC_GITHUB_APP_SLUG、KEYSTATIC_SECRET
分支保護ruleset protect-main：需經審稿才能合併，管理員例外
草稿命名後台開的草稿一律是 draft- 開頭

七、疑難排解

他說存不了檔他多半停在「正式版」上編輯。請他左上角先按另開草稿
後台打不開
或登入失敗		Vercel 的四個環境變數有沒有掉；改過變數要重新部署（Redeploy）才生效
合併了但網站沒變去 Vercel → Deployments 看那筆部署是否成功；靜態頁面需要重新建置，約 1–3 分鐘
文章封面圖不見圖片必須放在該篇文章專屬的資料夾。不要用檔案總管手動搬圖，一律從後台上傳
介面出現英文中文化是額外覆蓋的，遇到漏網的字截圖回報即可補上

八、長期原則

  1. 對外一律用筆名布克小姐，網站、repo、提交紀錄都不出現真名。
  2. repo 是公開的，提交紀錄會顯示協作者的信箱。請協作者在 GitHub 開啟 Keep my email addresses private。
  3. 合併就是發布。不確定的內容先退件，寧可多問一次。
